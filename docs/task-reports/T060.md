# T060 report

Status: accepted. T060 delivers candidate/PV/score analysis with a 5 Hz
throttle, human-versus-AI play whose every engine move is revalidated by Rust,
typed perspective conversion, a bounded SQLite analysis cache, conservative
light/standard/deep presets, lifecycle policy (window occlusion, low power,
memory pressure, idle helper reclaim), a `make benchmark` command, and a
fake-engine end-to-end suite. "基础规则模式" remains in place; no WXF
classifier, clock UI, or release work was started.

## Initial task understanding and planned boundary

T050 was committed (`673536a`) as an independent checkpoint before T060 began.
T060's allowed scope was UI/controllers, `PikafishKit`, cache, settings, and
tests/benchmarks. Per the user's explicit decision, "time-aware budget" means
engine-side budget derivation only: no persistent, undoable game clock, no
countdown, no timeout adjudication. Rust/FFI was not modified: engine-move
validation uses disposable Rust clones plus identity checks against the live
document.

## Summary

- Typed evaluation perspective: `PikafishEvaluationPerspective` (red /
  side-to-move) with `PikafishScore.displayed(in:sideToMove:)` covering cp and
  mate signs, ply semantics, and bounds; a full red/black × cp/mate ×
  bound matrix is fixture-tested. Raw values are never mutated.
- Validated budgets: `PikafishSearchBudget` with fixed (1…1,800,000 ms) and
  time-aware (Fischer-derived) kinds; the pure resolver never exceeds
  remaining minus a safety reserve and collapses to remaining/4 under critical
  time. The engine receives only the derived `movetime`.
- Typed resource presets: public surface is `PikafishResourcePreset`
  (light/standard/deep); arbitrary option tuples were made internal in T050 and
  remain internal. Preset application replays after every session
  (re)start, so a crash-recovered helper returns to budget values.
- Partial-info delivery: the session publishes a long-lived
  `AsyncStream<PikafishSearchUpdate>` with `.bufferingNewest(1)`; latest-info
  per MultiPV rank is aggregated (bounded at 3 ranks) and the terminal result
  carries all ranks. `MultiPV` is configured through a clamped typed API and
  degrades to 1 when the engine does not advertise it.
- SQLite analysis cache: one `AnalysisCache` actor over system SQLite3 (WAL,
  prepared statements, schema `user_version` migration, 256 MiB default disk
  with 64/256/1024 MiB choices, 32-entry/16 MiB memory LRU, monotonic LRU
  stamps, corrupt-database quarantine with bounded quarantine files, malformed
  payload = miss + single-row delete, busy/locked treated as soft failures,
  close fails closed). Only `PikafishValidatedFinalResult` can be stored.
- Cache identity: `AnalysisCacheKey` is a SHA-256 over every dimension in fixed
  field order (initial FEN, root-to-cursor UCCI history, profile ID/version,
  position hash, repetition hash, engine commit, NNUE hash, preset, budget
  kind/value, candidate count, schema versions). Swift `Hasher` is never used;
  each single-field change is fixture-tested to change the key.
- Coordinator: `NativeXiangqiAnalysisCoordinator` owns the sole
  `PikafishSession` and the cache; documents submit immutable requests. One
  active search at a time with cancel-then-wait arbitration; typed updates are
  throttled (200 ms default, clamped ≥100 ms) with at most one pending flush
  task; hidden windows stop the search; low power and memory pressure downgrade
  future presets and terminate the helper on pressure; explicit restarts are
  rate-limited to 5/hour; idle shutdown after 180 s.
- Asset verification moved off the main actor: `NativeXiangqiEngineAssetVerifier`
  (actor) returns a typed `NativeXiangqiVerifiedEngineDescriptor` (helper URL,
  engine commit, helper/NNUE hashes, NNUE bytes) used by the coordinator for
  launch and cache identity.
- Document integration: `analysisGeneration` invalidates stale output on every
  canonical operation (human move, undo/redo, navigation, FEN/UCCI replacement,
  close); analysis never changes the change count; every engine bestmove is
  validated through a disposable Rust clone before display, caching, or AI
  application; `(none)` is accepted only at a Rust terminal; AI replies flow
  through the shared Rust-backed commit path (undoable, persisted, change
  counted).
- Board overlays: `XiangqiBoardCandidate` now carries rank/from/to; the board
  draws candidate numbers at real destinations plus a best-candidate arrow;
  invalidation covers from/to squares; VoiceOver includes rank and move;
  the "非引擎界面提示" label is gone.
- Analysis pane: `AnalysisViewController` with a real `NSTableView`
  (rank/move/score/depth/nodes/NPS/PV), start/stop, retry (shown on failure),
  preset popup, perspective popup, AI-side popup, and the permanent
  "基础规则模式" label. Window occlusion/miniaturization stop analysis.
- App wiring: `AppDelegate` verifies assets off-main, opens the cache in
  Application Support, owns the coordinator, exposes it through
  `NativeXiangqiDocument.sharedAnalysisCoordinator`, installs memory-pressure
  and low-power observers, and best-effort shuts the helper down at
  termination. Documents created by NSDocumentController pick the service up in
  `makeWindowControllers`.
- Commands: `make benchmark-engine` (presets/stress/RSS/reclaim, JSON output,
  512 MiB gate) and `make benchmark` aggregate rules + UI + engine; the
  30-minute `--long-run` mode is opt-in. `memory-budgets.json` gains the 16 MiB
  memory-cache byte cap; the build-command contract documents T060 ownership.

## Design decisions and conflicts

1. Validation without Rust changes: T060's scope excludes Rust/FFI, so engine
   moves are validated on a disposable clone plus live identity checks
   (generation, node, position hash, repetition hash, profile). This matches
   the task boundary and keeps Rust the sole legality authority.
2. Cache key uses explicit FEN+history+hashes, not the 64-bit hashes alone:
   the hash-scheme version is not exposed through FFI, so hashes cannot be the
   persistent identity.
3. Coordinator arbitration is cancel-then-wait: a new request stops the active
   search and awaits its terminal before starting, so two requests never
   interleave inside one session; stale outputs are discarded by the document's
   generation checks.
4. SQLITE_BUSY is a soft failure, not corruption: quarantining on transient
   lock contention would wipe a healthy cache (observed and fixed during
   testing).
5. SIGPIPE is ignored in the session initializer: writes to a reaped helper's
   pipe otherwise terminate the app (observed as signal 13 in tests).
6. Memory LRU stamping uses a per-actor monotonic counter instead of wall-clock
   milliseconds so eviction is deterministic under fast successive writes.
7. The document holds a weak static `sharedAnalysisCoordinator` rather than a
   NotificationCenter observer for NSDocumentController-created documents;
   this avoids non-Sendable document capture in notifications.
8. AI replies are applied in a fresh MainActor task (not the analysis task)
   because `beginOperation` invalidates analysis — including cancelling the
   task that is about to apply the move.
9. Time-aware budgets stop at the engine: remaining time/increment are caller
   inputs; no clock state, no document fields, no adjudication (user decision).

## Known limitations and remaining risks

1. The 30-minute RSS/thermal run measures helper RSS via `proc_pidinfo`; CPU
   thermal state sampling requires privileged `powermetrics` and is left to the
   target-hardware release review (T090), with the RSS slope recorded here.
2. Throttle intervals are wall-clock based in the coordinator; the kit-level
   frequency contract (5 Hz default, 10 Hz hard) is enforced by constants and
   by the single-pending-flush design, not by a CI-injected clock.
3. Analysis restarts after every canonical change when enabled; selection
   queries also invalidate analysis (conservative, may stop analysis during
   piece selection).
4. The cache path is under Application Support and is not user-configurable in
   the UI yet (64/256/1024 MiB choices are implemented in code).
5. `MultiPV` is configured per session but not persisted in the document (by
   design: engine settings are not document content).
6. PV beyond the validated bestmove is displayed as engine text; only the
   rank-1 move is Rust-validated before overlays/AI.
7. Low-power handling stops deep searches and downgrades future presets;
   active searches under low power are stopped on the next request boundary
   rather than preemptively mid-search.

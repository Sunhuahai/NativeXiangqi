# T020 report

Status: accepted. T020 implements the canonical, engine-independent base Xiangqi
model, bounded codecs, variation history, and the additive production FFI needed by
the next UI task. It does not classify long-check or long-chase responsibility.

## Initial task understanding and planned boundary

Before editing, the first unfinished card was confirmed as T020 from `T010.md`, the
task-report directory, task index, and Git history. The intended scope was limited to
`xiangqi-core`, `xiangqi-io`, `xiangqi-ffi`, the local Swift wrapper, fixtures, and
build/test scripts. Planned risk checks were canonical Red-perspective coordinates,
strict but bounded FEN/UCCI input, failed-mutation atomicity, static archive ABI
compatibility, owned allocation/handle lifetime, and keeping the base profile from
claiming WXF adjudication. AppKit documents, Pikafish behavior, engines, assets,
network permissions, signing, and release automation were explicitly excluded.

## Summary

- Added a fixed 9×10 Rust position model with canonical standard FEN, all base
  piece movement constraints, self-check/flying-general rejection, checkmate, and
  stalemate-loss/困毙 semantics.
- Added deterministic position/repetition hashes, compact append-only variation
  nodes, stable IDs, exact apply/undo/redo/navigation, raw versioned ply evidence,
  and bounded annotations/history. The history API explicitly reports that WXF
  responsibility is unsupported.
- Added strict bounded FEN and UCCI codecs. Multi-ply UCCI imports are fully parsed
  into a candidate state before commit, reject a 4,097th token without collecting an
  unbounded token array, and preserve the source state on every failure.
- Evolved the generated C ABI additively from 1.0 to 1.1. It now provides
  non-reusable numeric game handles, fixed POD snapshots/square batches, navigation,
  FEN/UCCI/history operations, and explicit capacity/status values.
- Made all typed FFI output/in-out pointers reject null or misaligned addresses before
  dereference. Rust-owned buffers retain their T010 token ownership checks and now
  have explicit single-buffer and total-live-byte caps.
- Replaced the mutable Swift `@MainActor` game wrapper with a dedicated actor. It
  returns immutable snapshots, has explicit `close()` plus deinit fallback, routes
  all mutable FFI work through the actor, preflights UTF-8 byte counts before copying
  caller strings, and returns typed errors for closure, ABI, input, and mainline
  failures.
- Added fixed perft/rule/FEN/UCCI/FFI/Swift/C tests and an offline release D5 perft
  benchmark command.

## Design decisions and conflicts

1. Coordinates are Red-perspective (`a`–`i`, `0`–`9`), with index
   `rank * 9 + file`; FEN writes rank 9 through 0 and uses `N/B`, not historical
   horse/elephant aliases. The canonical start FEN is
   `rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1`.
   This was checked for UCCI interoperability against the pinned Pikafish source,
   but no engine code or result participates in Rust legality.
2. `Position` uses fixed 90-square arrays and deterministic, algorithmic v1 Zobrist
   keys. A `PieceId` is stable for a physical piece but deliberately excluded from
   the position hash; raw events retain it for future T070 evidence.
3. The variation tree is append-only and bounded at 4,096 nodes including root. Its
   tighter node ceiling also bounds live history before the separately checked 4,097
   entry history ceiling. Failed apply, replay, navigation, annotation, FEN replace,
   and UCCI import use candidate state and leave the visible state unchanged.
4. Strict setup validation rejects a general/advisor outside its palace, an elephant
   across the river, a pawn behind its possible starting rank, duplicate squares,
   invalid material counts, missing generals, and facing generals. Positions with a
   side currently in check remain legal imports so check-escape editing remains
   possible.
5. ABI 1.1 is additive only: T010 functions, status values, and capability values are
   unchanged. New functionality uses a monotonic `uint64_t` registry token rather
   than a caller-dereferenced `Box<Game>` pointer. Fixed-size POD responses avoid
   per-square FFI calls and every `reserved` field is checked/zeroed.
6. All output and in/out FFI pointer paths validate nullness and alignment before
   Rust `read`/`write`; a deliberately misaligned byte-buffer regression covers every
   typed pointer category. A C smoke also verifies a misaligned ABI-info pointer.
7. The Swift actor is intentionally not an AppKit type. Factories create/parse on the
   actor, and bounded UCCI/FEN operations do not execute on the main actor. Swift
   keeps only the opaque handle and disposable value snapshots, never an independent
   board or rule state.
8. The checked-in ABI generator was minimally extended for additive capabilities,
   statuses, POD declarations, function comments, and bounded numeric limits. It
   remains Python-standard-library-only and emits Swift numeric literals in the
   repository formatting style.
9. The required Codex-wrapper automation was attempted twice with the prescribed
   heredoc workflow, but `codex-wrapper` is not installed in this environment. This
   is `CODEX_FALLBACK`; direct edits/tests were used only after the two failed calls.

## Known limitations and remaining risks

1. The pinned stable Rust 1.97 compiler does not expose Rust's unstable sanitizer
   instrumentation. The test script reports that fact explicitly and C boundary ASan
   passes; `NATIVEXIANGQI_RUST_SANITIZER=require` remains fail-closed rather than
   falsely claiming Rust sanitizer coverage.
2. The base profile intentionally stores raw repetition evidence only. It returns
   `wxf_responsibility_supported = false` and neither decides long-check/chase nor
   labels a winner from repetition; T070 owns that classification.
3. The local XCFramework remains generated and ignored. A clean checkout must use a
   documented root command to stage it; no Xcode shell phase builds it implicitly.
4. Xcode 27.0 Beta was used. A toolchain update requires the relevant full command
   set to be rerun before any release use.
5. T000/T010 Community release blockers (helper/source/NNUE evidence, signing,
   notarization, and license review) remain unresolved and fail closed. T020 does
   not make a release eligible.

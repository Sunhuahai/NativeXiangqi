## Summary

1. Swift 6 warnings: all remaining warnings were in
   `NativeXiangqiAnalysisTests.swift` (unnecessary `await`, unused local); the
   suites now build warning-free (verified by a clean grep across builds).
2. `@unchecked Sendable`: zero occurrences in App and Packages sources
   (audited; only SwiftPM test-generated code contains none either — the audit
   covers first-party source only, which has none).
3. FFI ownership audit: the three T070 functions were re-checked —
   `xq_game_get_adjudication` allocates exactly one owned buffer released by
   the single `xq_ffi_buffer_release` path in the Swift wrapper (including the
   error path); `set_profile` functions allocate nothing; pointer
   nullability/writability validation and handle validation are present.
   `capabilityAdjudication` (512) was added to
   `XiangqiCoreBinary.requiredCapabilities` so incompatible binaries fail the
   typed ABI check before any adjudication call.
4. Diagnostics privacy: every `documentLogger`/`applicationLogger` call was
   reviewed — they log only stable `diagnosticCode(error)` values with
   `privacy: .public` on codes and never game records, comments, user paths, or
   engine output.
5. Accessibility: keyboard navigation, VoiceOver virtual squares, non-color
   candidate labels, and system-color drawing were re-verified; the board has
   no animation code, so Reduce Motion is satisfied by construction; high
   contrast follows system colors. The T030/T060 accessibility tests pass
   unchanged.
6. Localization infrastructure: `XiangqiDocumentKit` now carries
   `Resources/zh-Hans.lproj/Localizable.strings` and `en.lproj/...` with
   `defaultLocalization: "zh-Hans"`; `NativeXiangqiLocalized` resolves keys via
   `Bundle.module` and never leaks keys. The analysis pane's buttons, popups,
   and status texts were migrated; the Xiangqi/WXF term table
   (`docs/15-localization-and-terms.md`) records the human-reviewed terms
   (将/帅/士/象/马/车/炮/兵/将军/应将/将死/困毙/长将/长捉/兑/闲/须变着/和/
   不支持/存疑 with English equivalents).
7. Recovery drills: mapped the existing passing tests to the required drill
   set — autosave/version recovery (T040 smoke), corrupt document/migration
   (T040 format + fuzz), corrupt cache and missing helper/NNUE (T060/T050),
   crash/forced-stop and restart limits (T050 fake scenarios, T060 coordinator)
   — no new data-loss path found; the one observed data point (a flaky
   log-read race in a T050 test) was fixed with the existing bounded poll

8. Bundle/resource/architecture audit: arm64-only build settings re-verified

9. Regression dashboard: `scripts/regression-dashboard.sh` +

## Design decisions and conflicts

1. Localization scope: infrastructure plus high-frequency pane strings were
   migrated; menus, coordinates, and document status strings remain direct
   Chinese and are recorded as a T090-before-release cleanup item. The term
   table is the single source of truth; UI text contradicting it is a defect.
2. The regression dashboard aggregates already-cheap gates rather than
   re-running the whole suite, so `make test` semantics stay unchanged and the
   dashboard is fast and offline.
3. Adding ADJUDICATION to required capabilities means Debug builds now reject a
   hypothetical older static library; this repository always builds the
   artifact from the same source, so the strict check is safe and fail-closed.

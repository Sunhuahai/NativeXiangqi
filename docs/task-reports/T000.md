## Design decisions and conflicts

1. The only Xcode scheme is NativeXiangqi with Debug and Release configurations.
   ARCHS is arm64, MACOSX_DEPLOYMENT_TARGET is 15.0, Swift language mode is 6,
   strict concurrency is complete, App Sandbox and Hardened Runtime are enabled, and
   the entitlement set contains only com.apple.security.app-sandbox.
2. The app target has no shell build phase or package reference. make build disables
   automatic package resolution and performs policy/network checks before invoking
   xcodebuild.
3. The task card requires cargo metadata --locked --format-version 1 from repository
   root, while the lower-priority architecture sketch places Cargo.toml under Rust/.
   Cargo does not auto-discover child manifests. The root acceptance command was
   prioritized, so the workspace manifest and lock are at root while crates remain
   under Rust/crates. This is a small, reversible divergence from the sketch.
4. Community release authorization is hard-coded to the repository policy file.
   Environment variables and alternate config paths are ignored; commercial, paid,
   IAP, subscription, donation-gated, Mac App Store, and unknown modes fail.
5. A development manifest may carry declared unresolved fields but is always
   release_eligible = false. Release manifests must have no unresolved values, a
   bundled helper/network, immutable network evidence, and prepared corresponding
   source.
6. Pikafish profile-build invokes the upstream net target. Future release tooling must
   pre-stage a byte-counted, hash-verified NNUE and run without network access; T000
   does not invoke the build.

## Known limitations and remaining risks

1. Xcode 27 Beta successfully lists and builds the project, but the repository pins
   Xcode 26.x stable. Compatibility on a newer Beta does not satisfy the pinned
   toolchain acceptance gate. T000 must not be marked complete until the exact commands
   pass with Xcode 26.x selected, or a separately reviewed toolchain-baseline change is
   explicitly authorized.
2. Global xcode-select still points to CommandLineTools because changing it requires an
   administrator password. DEVELOPER_DIR was used only for compatibility validation.
3. The master-net release asset is mutable. Its observed asset ID, bytes, and digest
   are development evidence only; a release must preserve immutable input bytes and
   reverify rights.
4. NNUE commercial permission, helper hash, corresponding-source archive/hash, offline
   helper rebuild, nested signing, and archive sandbox execution remain unresolved and
   fail closed.
5. The GitHub-generated source archive hash records the exact bytes observed on the
   verification date. A release must preserve those bytes or create and lock a
   reproducible corresponding-source archive.

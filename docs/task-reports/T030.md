# T030 report

Status: accepted. T030 delivers the native, in-memory AppKit Xiangqi play shell
and board while deliberately leaving the lossless player-document format to T040.
Rust remains the sole authority for every position, legal move, terminal state, and
variation navigation.

## Initial task understanding and planned boundary

T020 was accepted, and T030 was confirmed as the first unfinished task from the
task reports, task index, Git history, and clean predecessor worktree. The allowed
scope was the AppKit document/window shell, `XiangqiUI`, `XiangqiDocumentKit`,
geometry/UI tests, offline commands, and an idle UI baseline. No final `.xqgame`
format, FEN panel, engine, WXF full mode, theme system, network permission, signing,
or release policy expansion was planned.

The main pre-change risks were AppKit/Swift 6 isolation; ensuring Rust work never
blocks the main actor; bounded cancellation and stale-result handling; not creating
an authoritative Swift board/tree; red/black transforms; VoiceOver/keyboard input;
dirty-document close behavior before a real writer exists; and offline local-package
builds. The required Codex wrapper was attempted twice before direct work; it was not
installed, so this task used the documented `CODEX_FALLBACK` path.

- Replaced the T000 manual window with `NSDocument`, a window controller, native
  menus/toolbars, and a real three-pane `NSSplitViewController`: variation outline,
  custom Core Graphics board, and an explicit no-engine analysis placeholder.
- Added immutable, pure, `Sendable`/`Equatable` 9×10 geometry with canonical
  Red-perspective square IDs, backing-scale pixel snapping, clipped invalidation,
  hit tolerance, and red/black presentation transforms.
- Added one custom `XiangqiBoardView`, cached drawing inputs, no square subviews or
  layers, 90 stable virtual accessibility elements, non-color overlays, keyboard
  focus, pointer/keyboard/AX input, fake bounded non-engine candidates, and exact
  visible `基础规则模式` labeling.
- Added a per-document bounded operation/generation model. Rust calls remain on
  `XiangqiCoreGame`; cancellation/close closes the actor handle, stale results are
  rejected, and a post-mutation snapshot failure quarantines the session rather than
  showing an old Swift snapshot as current state.
- Added native UndoManager actions distinct from history browsing; branch display is
  a bounded, disposable Rust-node-ID ledger and every navigation is revalidated by
  Rust. Cmd+Left/Cmd+Right navigate to the true root/leaf; Shift+Cmd+Z is explicitly
  bound for redo.
- Added a test-only bounded NSDocument autosave lifecycle smoke that round-trips an
  exact marker only. The player document still rejects all Save/Open reads/writes
  until T040 can persist the complete tree without data loss. Untitled dirty windows
  retain the default native Save/Don't Save/Cancel confirmation; there is no silent
  discard or fake save success.
- Added offline UI/integration/benchmark commands and a fail-closed local-package
  policy update. The benchmark displays a real Rust-ready document window before
  measuring RSS and measures real synthetic pointer-event-to-board-delegate input.

## Design decisions and conflicts

1. Rust is canonical. `NativeXiangqiDocument` holds only an immutable snapshot,
   selected square, highlights, flip state, last-move hint, and bounded display
   ledger. The ledger is never used to decide legality or adjudication; selecting a
   node calls Rust navigation. It is capped at the current Rust limit of 4,096 nodes
   and detects missing/cyclic entries without mutating Rust.
2. T020 has no child-enumeration ABI and T030 must not build an independent Swift
   variation tree. The outline therefore records only moves that Rust already
   accepted in this local session. It is explicitly disposable UI metadata, not a
   persistence or rules substitute. T040 owns lossless document serialization.
3. AppKit/document/view state is `@MainActor`; `XiangqiCoreGame` remains a separate
   actor. Each document permits one in-flight operation. A continuation-based,
   bounded readiness wait has one waiter and one timeout task; timeout cancels the
   pending initialization and returns a typed error. A debug-only regression fixture
   covers timeout, cancellation, and cleanup without entering Release builds.
4. Normal native Undo/Redo calls `UndoManager`; left/right history browsing and
   outline navigation clear stale undo actions rather than mixing presentation
   browsing with document mutations. Failed operations add no phantom undo action.
5. The task card asks for a temporary autosave smoke but permanent docs require a
   complete branching record. The safe reversible choice is an isolated NSDocument
   smoke marker, capped to 26 bytes, never exposed as player data. Player Save/Open
   fail closed. A dirty in-memory player document uses the default native explicit
   Save/Don't Save/Cancel close confirmation; choosing Save reports the typed
   unavailable error, and only an explicit discard loses the session.
6. The benchmark’s idle sample is after a visible three-pane document and a
   Rust-ready local session, before the separate bounded offscreen board used for
   draw/input measurements. `task_info` failure is nonzero, not a zero-RSS success.
7. The policy verifier permits exactly the two repository-local dependencies of
   `XiangqiDocumentKit`, rejects all remote declarations, forbids direct C FFI use
   outside `XiangqiCoreBinary`, and scans only package `Sources`/`Tests` rather than
   ignored SwiftPM build output.

## Known limitations and remaining risks

1. Player persistence, migration, recovery, format versioning, FEN/UCCI panels, and
   lossless outline reconstruction are intentionally absent until T040. A user must
   explicitly choose the standard native discard option to close an unsaved in-memory
   session; Save reports a recoverable unavailable error.
2. The variation outline covers locally accepted moves only and is not a serialized
   record. Rust remains authoritative even when an outline entry is missing.
3. The right pane has only bounded non-engine UI hints. Pikafish, engine lifecycle,
   NNUE, caching, and full WXF adjudication are out of scope.
4. Measurements use Xcode 27.0 Beta; rerun the required command set after toolchain
   changes. T000/T010 Community signing, source, engine, NNUE, and notarization
   blockers remain unresolved and fail closed.

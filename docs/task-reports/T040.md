# T040 report

Status: accepted. T040 replaces the T030 temporary persistence with the
versioned `.xqgame` v1 document: bounded JSON envelope, explicit rule profile,
flat Rust-replayed variation tree with selections and annotations, preserved
unknown extensions, v0 migration, real `NSDocument` save/save-as/autosave/version
recovery, strict FEN/UCCI interchange, deterministic fuzz corpora, and removal
of the temporary T030 format. Rust remains the sole authority for every
position, move, tree, and terminal state; Swift never keeps an independent board
or legality truth.

## Initial task understanding and planned boundary

T030 was accepted, and T040 was confirmed as the first unfinished task from the
task index, Git history (`bd6edcf` T030 tip), and the working tree. The allowed
scope was `xiangqi-core`/`xiangqi-io`/`xiangqi-ffi`, `XiangqiDocumentKit`,
document UI, fixtures/fuzz/tests. No XQF writer, Pikafish process, or final WXF
classifier was planned.

Planned verification facts: `.xqgame` v1 schema fields and limits; bounded JSON
decode with typed field diagnostics; migration that can never overwrite its
source on failure; FEN import/export with explicit initial/current semantics;
transactional UCCI mainline import with exact failing ply; preservation of
unknown extensions on round trip; NSDocument change-count/autosave/restore
transitions; one Rust owner per prepared open.

Main risks: Swift 6/MainActor isolation around `NSDocument` concurrent reads;
exactly-one-owner handoff of the Rust restore token; change-count correctness
for browsing/cursor content; NSFileCoordinator-based save/recovery behavior in
the execution environment; keeping engine/UI presentation state out of the
document and out of the change count.

## Summary

- Added `.xqgame` v1: `schemaVersion`, `documentID`, `metadata`, `initialFEN`,
  explicit `ruleProfile` (id/version/snapshot), flat `variationTree`, `currentNode`,
  `annotations`, `result`, and `extensions`. Unknown top-level fields and safe
  extension values survive round trips.
- Added bounded JSON decode/encode: depth, value count, string bytes, entry
  count, number length, total file bytes (64 MiB), nodes (4,096), tree depth
  (4,096), annotation bytes per node (64 KiB) and total (16 MiB), and FEN bytes
  (4 KiB); every limit fails with a typed, field-addressable error.
- Added a pure in-memory v0 migration into the v1 envelope (one reserved
  `org.nativexiangqi.migrated-v0` namespace), plus malformed/old-version
  fixtures and a deterministic malformed corpus. A failed migration never
  writes the source and never installs a half-imported state.
- Added the Rust FFI document restore transaction: `create from FEN`, bounded
  append/annotation/navigate/select operations against an unpublished
  candidate, invalidate-on-first-failure, and a `finish` that publishes only a
  healthy candidate. Malformed or out-of-order flat records now report
  `STATUS_PARSE_ERROR` (new `CorruptDocument` core error) instead of a
  misleading internal-error class, while internal invariants keep
  `STATUS_INTERNAL_ERROR`.
- Added FEN diagnostic create/replace (exact field) and UCCI mainline import
  (exact 1-based failing ply) with clone-and-commit; failed import never
  mutates the live game. FEN export distinguishes initial vs current scope.
- Added `NSDocument` open/save/save-as/autosave with AppKit's change counting,
  autosave-in-place, version browsing via a local-version catalog that reads
  only `hasLocalContents` versions, and a fail-closed `revert(toContentsOf:)`.
  Prepared open replays the full tree in Rust off-main before any window state
  is installed; URL opens now carry the coordinated read's modification date so
  AppKit's external-change detection stays enabled.
- History browsing and branch navigation move the persisted cursor and now mark
  the document edited (same rationale as the retained-variation undo path), so
  closing a clean saved game after browsing cannot silently drop the cursor.
- Removed the T030 temporary autosave smoke persistence; player documents are
  only `.xqgame`. UI state (flip, selection, analysis placeholder, status text)
  never dirties the document.
- Added `make fuzz-smoke` (deterministic offline Rust + Swift corpora, 512
  inputs each, ≤1 KiB per input, fixed 180 s wall deadline per subprocess,
  Cargo `--offline`) and wired it into `make test`.
- Added `max_live_document_restores` (2) and document capability bits to the ABI
  manifest; the generated C header/Rust/Swift projections and the committed
  digest stayed in sync (verified by `verify-generated-ffi`).

## Design decisions and conflicts

1. The `.xqgame` envelope lives in Swift (bounded JSON) while the canonical core
   snapshot (initial FEN, profile, flat tree, selected child, annotations) is
   replayed by the Rust FFI restore transaction. Unknown extensions therefore
   never cross the bounded C owned-buffer ABI, and Swift never owns a board or
   legality truth. `AGENTS.md`'s Rust-authority rule is preserved.
2. AppKit's synchronous Version Browser hook cannot block on large-file/Rust
   work, so `revert(toContentsOf:)` fails closed with a recoverable field error;
   the app's own local-version command runs the bounded candidate read/replay
   under `performActivity` + `performAsynchronousFileAccess` and installs only
   on success, matching docs/06.
3. Restore failures distinguish corrupt document data (`CorruptDocument` →
   `STATUS_PARSE_ERROR`) from internal invariant violations, satisfying the
   exact-failure reporting requirement without weakening fail-closed behavior.
   One reviewer conflict resolved: the earlier classification surfaced both as
   `STATUS_INTERNAL_ERROR`, which would have made Swift diagnostics misleading.
4. The persisted cursor (current node / selected child) is document content;
   history browsing and navigation now `updateChangeCount(.changeDone)`.
   Navigating to the already-current node is a no-op and stays clean.
5. FEN syntax itself is validated only by Rust candidates; the Swift envelope
   validates structure, bytes, and bounds. Every open/import path replays Rust
   before install, so an invalid FEN can never be serialized as an openable
   document. This is a deliberate delegation, not a gap: Rust is the authority.
6. Entitlements now allow `com.apple.security.files.user-selected.read-write`
   (required for sandboxed document save/open panels) in addition to App
   Sandbox; the no-network check asserts exactly these two keys and no network
   entitlement.
7. Environment conflict recorded: inside the restricted execution environment,
   `NSFileCoordinator` fails (NSCocoa 256, accessor never called), so the five
   file-coordination tests (oversize preflight, v0 migration file-read,
   save/save-as/autosave/restore, local-version recovery) could not run there.
   Per the T030 precedent, full-host execution was required; with the sandbox
   disabled the suites pass 34/34 then 35/35. The implementation was unchanged
   by this discovery; the failures were environment-only.

  leaves source bytes and live document untouched; user-entered initial FEN

## Known limitations and remaining risks

1. `data(ofType:)` can serve pre-mutation bytes if a save races an in-flight
   operation; AppKit's change-count mechanism schedules a follow-up save, so
   this is eventually consistent by design (never block the main thread).
2. The variation outline calls `reloadData()` per presentation render; fine at
   human interaction rates, but T080 must throttle it once engine analysis
   reaches 5 Hz.
3. The window title is fixed in the window controller; document display name
   changes after Save As are not reflected in the title bar (the edited dot
   still works). Consider wiring `displayName` in T080.
4. The v0 migration reserves one extension key (`org.nativexiangqi.migrated-v0`);
   a legacy v0 extension using that exact key would be superseded (extremely
   unlikely, documented in code).
5. "还原到已保存版本" remains enabled for never-saved documents and ends in a
   recoverable status error; validation refinement is deferred.
6. Measurements and file-coordination tests use Xcode 27.0 Beta and macOS 27.0;
   rerun after toolchain changes. T000/T010 signing, engine, NNUE, and
   notarization blockers remain unresolved and fail closed.

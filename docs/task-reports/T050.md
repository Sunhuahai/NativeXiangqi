Status: accepted. T050 builds and bundles the pinned Apple Silicon Pikafish
helper with its matching NNUE, implements the typed, bounded `PikafishSession`
UCI actor, proves the archived sandbox helper, archives exact corresponding
source with byte-identical rebuild verification, and keeps every unsafe release
mode fail-closed.

## Summary

- Vendor lock corrected: T000's mutable `master-net` NNUE (51,585,654 bytes,
  verified 2026-08-09) carries network version header `0x6a448afa` and is
  REJECTED by the pinned engine (expects `0x7AF32F20`). The network shipped
  inside the engine's own release archive `Pikafish.2026-01-02.7z`
  (`pikafish.nnue`, 53,212,941 bytes, SHA-256
  `c4026370…4d5f77`, version header `0x7AF32F20`) matches the engine, so the
  lock moved to the release archive (archive SHA-256 and byte count recorded in
  the manifest; correction recorded in `licenses/NETWORK-LICENSE.md`).
- `make vendor-verify` is the only networked engine command: it fetches the
  locked source archive and engine release archive, verifies SHA-256/bytes,
  extracts and verifies the NNUE (including the decompressed version header),
  re-runs the pinned source's `make help`, and enforces the recorded output.
- Helper built offline with `make build ARCH=apple-silicon COMP=clang
  GIT_SHA=ce0679e0 GIT_DATE=20260103`: `make help` confirms the `apple-silicon`
  target; the non-PGO `build` target is used because `profile-build` output is
  timing-dependent and would make byte-level rebuild verification impossible.
  Two consecutive builds produce identical SHA-256 (`48dbe0c7…42d9d8`,
  752,808 bytes), so `verify-source` can byte-compare.
- The upstream Makefile's `git rev-parse` probes the enclosing NativeXiangqi
  repository; `GIT_SHA`/`GIT_DATE` are pinned to the engine's own locked commit
  (`ce0679e0`, `20260103`) so the binary carries the engine identity and stays
  deterministic.
- `make engine-smoke`: real helper handshake (`id name Pikafish 2026-01-02`),
  `isready`, and fixed-FEN `go movetime 300` produce a bestmove; missing and
  corrupt NNUE runs disable analysis with bounded diagnostics and no bestmove.
- `PikafishKit.PikafishSession` actor implemented: launch via
  `Process.executableURL` with explicit arguments; UCI handshake with dynamic
  option discovery; whitelist presets (light/standard/deep) that set only
  advertised options with values inside advertised ranges; `isready`/
  `ucinewgame`/`position`/`go`/`stop`/`quit`; bounded stdout/stderr line reading
  with truncation and overflow markers; typed `info`/`bestmove` parsing with
  range-validated numbers and UCCI-move syntax checks; per-search generation,
  deadline, stop/cancel path, and exactly one terminal result or typed failure;
  crash detection and bounded restart; graceful shutdown (`stop` → `quit` →
  bounded exit wait) with forced termination fallback; unknown tokens ignored
  with bounded diagnostics.
- The pipe reader uses raw `Darwin.read` in nonisolated drain tasks: on this
  OS/toolchain, Foundation's `FileHandle.read(upToCount:)` blocks indefinitely
  when a `readabilityHandler` is installed, and actor-inherited drain tasks can
  freeze the main actor; both failure modes were diagnosed with `sample`/`lsof`
  and eliminated.
- Engine fakes (C, scenario via `FAKE_SCENARIO`): normal, option-variants,
  option-not-advertised, slow-handshake, slow-isready, flood, stderr-flood,
  malformed, no-bestmove, ignore-stop, crash-on-go, crash-early,
  illegal-bestmove. All 26 PikafishKit tests pass, including the real-helper
  smoke gated on the verified artifacts.
- App embedding: `make build` copies the verified helper and NNUE plus the full
  license/notice set and the locked manifest into
  `Contents/Resources/Engine/`, and ad-hoc signs the nested helper. The
  analysis placeholder pane shows a bounded engine-asset status
  (available/missing/invalid) computed offline from the embedded manifest;
  engine/UI state never dirties the document.
- `make verify-signing` proves the archived sandbox helper: embedded NNUE
  matches the lock, the embedded helper's ad-hoc signature is valid and its
  code-directory hash equals a same-identifier signature of the locked artifact
  (codesign rewrites are not byte-reversible, so raw hash comparison is
  impossible), and the embedded helper completes a handshake and fixed-FEN
  search inside a restrictive sandbox with network denied.
- `make archive-corresponding-source` builds the immutable corresponding-source
  archive (exact tree from the verified tarball, the pinned-version patch,
  licenses/notices, build instructions, checksums) deterministically (fixed
  mtimes, `gzip -n`); `make verify-source` extracts it, verifies the tree
  content digest, applies the patch, stages the verified NNUE, rebuilds offline
  under a network-denying sandbox, and byte-compares the executable with the
  locked helper hash. PASS.
- Final review hardened terminal ownership before acceptance: the search
  continuation is installed before `go`; handshake/readiness/search/stop timers
  are retained and cancelled on every terminal path; shutdown resolves an
  in-flight search; `position` is ready-only; idle helper exits become a typed
  failed state; pipe reads retry `EINTR`; and searches beyond the diagnostic
  line-accounting cap continue retaining the newest typed `info` value.
- Preset construction is no longer public outside `PikafishKit`, and option
  values reject control characters before any `setoption` is written. The app
  surface remains limited to the fixed light/standard/deep presets.
- Corresponding-source verification is now unconditionally offline: neither
  `make archive-corresponding-source` nor `make verify-source` depends on or
  invokes `vendor-verify`. Missing local vendor inputs fail closed with an
  explicit instruction to run the separately networked command.
- Final verification caught a stale tree digest embedded in the first source
  archive. The archived tree was byte-equivalent to the locked vendor source,
  but its recorded digest was wrong. Regenerating the deterministic archive
  offline produced tree digest `c101e36d…f3af0d` and archive SHA-256
  `7c234ae2…d5bba`; `verify-source` then rebuilt the same locked helper

- Development manifest updated: resolved helper path/hash/bytes, resolved
  corresponding-source archive hash and tree digest, one hashed patch entry,
  deterministic build command with rationale, and the corrected network lock
  with `release_asset_mutable = false`. `network.written_commercial_permission`

## Design decisions and conflicts

1. The mutable master-net NNUE was proven incompatible with the pinned engine
   (version header mismatch). The lock moved to the network shipped inside the
   engine's own release archive; the correction and evidence are recorded in
   the manifest and license evidence files. This is a supply-chain correction,
   not a license change: the release's `NNUE-LICENSE.md` states the same terms
   as the Networks repository README.
2. The deterministic `make build` target replaces the provisional
   `profile-build` command from the T000 manifest. `make help` (committed)
   confirms the target exists; the rationale (PGO output is timing-dependent,
   preventing byte-level rebuild verification) is recorded in the manifest.
3. `GIT_SHA`/`GIT_DATE` are pinned to the engine commit because the upstream
   Makefile probes the enclosing repository's git metadata, which would embed
   NativeXiangqi's own commit hash into the engine binary.
4. Raw `Darwin.read` drains in nonisolated tasks are used for pipe I/O after
   diagnosing two environment-specific failures: FileHandle reads blocking
   indefinitely with a readabilityHandler installed, and actor-inherited drain
   tasks freezing the main actor. Both were reproduced with `sample`/`lsof` and
   fixed with the final design.
5. codesign rewrites are not byte-reversible, so `verify-signing` proves helper
   identity via the code-directory hash of a same-identifier signature instead
   of a raw byte hash.
6. The corresponding-source archive is deterministic (fixed mtimes, `gzip -n`)
   and committed; the NNUE is deliberately excluded (separate license) and only
   its hash, byte count, and license text are archived.
7. The development manifest is not release-eligible; commercial NNUE permission
   remains unresolved and all commercial/paid/MAS gates stay disabled.

## Known limitations and remaining risks

1. NNUE commercial permission remains unresolved; Community distribution is
   legal-use-only per the upstream license text until written permission or
   validated alternative assets exist (T000 gate, unchanged).
2. The helper is unstripped; a release build may strip it (T090), which changes
   the executable hash and requires re-recording the lock and re-verifying
   source.
3. `verify-signing` proves the Debug archived app with ad-hoc signing; the
   Developer ID + notarization path and a clean-account test remain T090.
4. `make build` embeds from the gitignored vendor/artifacts caches; a fresh
   clone must run `make vendor-verify` before building (documented, fail-fast).
5. The engine-status pane is a shell placeholder; analysis UX, AI play, and
   cache integration are T060.
6. `make help` output normalization strips upstream trailing whitespace from
   the committed record; the comparison remains exact otherwise.

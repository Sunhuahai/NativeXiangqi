## Design decisions and conflicts

1. `ffi-api.toml` is the single checked-in ABI source. The generator uses Python's
   standard library only, rejects oversized/invalid manifest fields, and has a
   deterministic `--check` mode. This avoids introducing a code-generation download
   path while satisfying the required generated C header.
2. The public ABI is five `xq_ffi_*` C functions with fixed-width `repr(C)` POD
   structures. All externally reachable pointers, output structures, capacity,
   caller-provided ABI numbers, and buffer ownership fields are validated. Panics are
   caught before crossing the ABI boundary.
3. An owned buffer carries a monotonic 64-bit allocation token in addition to its
   pointer, length, and capacity. The registry validates the complete tuple before
   removing/freeing it and fails closed on token exhaustion. This prevents a copied,
   stale buffer descriptor from releasing a later allocation that reused the same
   address (the ABA case).
4. An Apple static archive contains Rust implementation globals in addition to C ABI
   entry points. The inspector parses bounded Mach-O `LC_SYMTAB` data from only the
   bounded `xiangqi_ffi-*` archive members, records the five actual C ABI symbols,
   rejects missing/unexpected `xq_ffi_*` symbols, and also C-links/runs the smoke
   program. Metadata explicitly scopes other static-archive symbols as non-C-ABI.
5. An XCFramework cannot select Debug and Release variants for the same macOS/arm64
   slice. Both artifacts remain under ignored `build/rust-artifacts`; the selected
   configuration is explicitly staged into the one local SwiftPM binary-target path.
   `make rust-build`, `make swift-test`, and `make build` do this before consuming
   the package. A clean checkout must use one of those root commands, never a
   prebuilt checked-in binary.
6. The pinned Rust 1.97 stable compiler cannot enable Rust's unstable sanitizer
   instrumentation. The default test config therefore exercises the C boundary with
   AddressSanitizer and emits an explicit unsupported-coverage notice; setting
   `NATIVEXIANGQI_RUST_SANITIZER=require` fails rather than implying Rust coverage.
   The script will enable supported Rust sanitizer flags on an appropriate toolchain.
7. No `PBXShellScriptBuildPhase` was added. The Xcode project references only the
   local package, and the root build script performs offline artifact staging before
   `xcodebuild -disableAutomaticPackageResolution`.
8. The required Codex-wrapper attempt could not run because `codex-wrapper` was not
   installed in this execution environment. This is recorded as `CODEX_FALLBACK`;
   implementation proceeded directly under the skill fallback and the wrapper should
   be retried for the next task.

## Tests added or changed

  bounded UTF-8 build information, double/forged release rejection, 100,000 owned
  buffer lifecycles, explicit live-buffer exhaustion/recovery, and stale-token
  address reuse. The suite is serial because the bounded allocation registry is
  process-global by design.

  executes under configurable C AddressSanitizer by default.
- Swift tests verify compatible ABI/build information and incompatibility rejection
  for major, minor, capability, and reserved-field mismatches.
- The artifact inspector verifies arm64 architecture, bounded size/member parsing,
  actual C ABI symbols, C linker/runtime use, SHA-256, toolchain, and metadata.
- CI regenerates all projections and fails if their checked-in diff is nonempty.
- The existing no-build-downloads check now permits exactly the local binary package
  and requires its offline artifact-staging contract.

## Known limitations and remaining risks

1. The Rust compiler is pinned to a stable version that cannot provide the requested
   unstable sanitizer instrumentation. C boundary ASan coverage is present; a future
   supported Rust sanitizer toolchain must rerun the suite rather than treating this
   as equivalent coverage.
2. The binary XCFramework is intentionally ignored. Direct SwiftPM/Xcode invocation
   in a pristine checkout will not resolve it until the documented root command
   stages a freshly built artifact; no Xcode shell phase silently builds it.
3. The static archive boundary is intentionally minimal and is not a rules engine.
   Rust remains the future sole rules authority, but T020 must introduce those rules
   without widening this ABI beyond documented needs.
4. The verification used an Xcode 27 Beta. Any later Beta/stable update needs the
   relevant full verification set rerun before release use.
5. T000's helper/NNUE/source/license/signing/notarization release blockers remain
   unresolved and fail closed. T010 does not make any build release eligible.

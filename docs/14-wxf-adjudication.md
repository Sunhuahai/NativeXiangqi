# 14. WXF 风格重复判罚快照（T070）

## 1. 快照身份与出处

- 档案名称：`wxf-2011-basic-v1`（profile id 2，version 1，`RuleProfile::WxfV1`）。
- 出处：本快照实现的是象棋重复局面责任判罚的**公共子集**，依据中文通行
  判例文本（《象棋竞赛规则（2011）》关于重复局面与长将/长捉的一般规定，
  以及亚象联《象棋比赛规例》的对应条目）中各方一致的表述整理而成。
  项目不声明本快照等同于任何单一机构的完整赛事规则文本；完整赛事判罚
  （将/捉/闲完整优先级表、联合捉子、兑的细分等）明确不在本快照内。
- 术语映射（实现内名称 → 中文惯例）：

  | 实现 | 中文 | 含义 |
  |---|---|---|
  | `PlyClassV1::Check` | 将 | 行棋后将军 |
  | `PlyClassV1::Chase` | 捉 | 行棋后攻击（可吃但不吃）一个无根/根不足或价值较低的对方子 |
  | `PlyClassV1::Exchange` | 兑 | 攻击一个有根且价值不高于己子的目标 |
  | `PlyClassV1::Idle` | 闲 | 非将非捉非兑 |
  | `VerdictV1::MustChange(side)` | 须变着 | 长将/长捉方须变着，不变判负 |
  | `VerdictV1::Draw` | 和 | 双方不变作和 / 双方长将判和 |
  | `VerdictV1::Unsupported` | 不支持 | 快照无定义，不判胜负 |
  | `VerdictV1::Ambiguous` | 存疑 | 证据不足以唯一判定 |

## 2. 每着标签与证据

每个已应用着法在 `WxfPlyLabelV1` 中记录：行棋方、着法、类别、将/应将、
以及捉目标的保护与价值对比证据。标签只派生自 Rust 规范事件与局面；
**从不使用 Pikafish 评分**。保护判定为“对方任意一子可攻击目标格”。

价值量表（仅用于兑/捉判定，单位为一车之十分之一）：将 1000、车 90、
炮 45、马 40、士/象 20、兵 10。

## 3. 循环检测与责任分类分离

- 循环检测：对当前局面在根到光标路径上统计同哈希出现次数
  （位置哈希含行棋方）；达到 `MIN_REPEAT_COUNT_FOR_ADJUDICATION`（3 次，
  含当前）后，以最近两次出现之间的着法段为循环。
- 责任分类：只消费循环内的 `WxfPlyLabelV1`；均匀模式直接判定，混合模式
  一律 `Unsupported`（绝不猜测胜者）。

## 4. 已判定模式（均匀循环）

| 循环内红/黑着法 | 结论 |
|---|---|
| 红全将 / 黑任意 | 红方长将，须变着 |
| 黑全将 / 红任意 | 黑方长将，须变着 |
| 双方全将 | 双方长将，判和 |
| 红长捉同一子 / 黑长闲 | 红方须变着 |
| 黑长捉同一子 / 红长闲 | 黑方须变着 |
| 双方全闲 | 双方不变作和 |

## 5. 明确不支持/存疑

- 混合模式（一将一闲、将捉混合、捉闲混合、兑与闲混合等）；
- 交替目标（长捉多个不同子）；
- 多目标单着（一着同时攻击多个子）；
- 双方长捉同一目标 / 不同目标；
- 互将（双方长将）已有判定，但**合法互将完整对局样例尚未收录**，
  该覆盖项以分类器向量测试替代并标记待人工评审；
- 黑方长将镜像同理。

## 6. 语料与评审门

- 全局面夹具：长将（红）、长捉（红炮捉马）、双方长闲、profile 切换与
  undo/redo 证据保持（`xiangqi-core/tests/adjudication_corpus.rs`）。
- 分类器向量：互将、一将一闲、交替目标、兑对闲、黑方长将镜像。
- 预期标签由作者人工推理并写入测试；**发布前需独立人工评审**
  （AGENTS.md 门）。评审通过前 UI 保持“基础规则模式”徽标；通过后仅对
  WxfV1 档案切换徽标，绝不暗示完整赛事判罚。
